# Phase 3.17 — Deploy & Demo Walkthrough

**Status:** DRAFT — expand to READY before implementing
**Milestone:** M1 Growth loop
**Requires:** 3.16
**Unlocks:** M2

## Goal

The loop is reachable at a public URL, and the README opens with a demo anyone
can follow in under a minute.

**This is M1's exit condition.** Until it is done, the loop exists only on your
machine, which for a portfolio is close to not existing.

## Why this is a phase and not an afterthought

A recruiter spends well under a minute on a repository. What converts is a link
that works and a first screen that shows the thing running. Everything in M0 and
M1 is invisible without this.

## Scope

- Deploy to Vercel (or equivalent); production database on Neon
- Environment configuration: `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, Razorpay
  test keys, the Anthropic API key — **none committed**
- `prisma migrate deploy` in the build, never `migrate dev`
- Seed the production database with the four stores
- Razorpay webhook pointed at the deployed URL
- A demo walkthrough in the README: exact URL, demo credentials, the click path
- A GIF or short recording of the complete loop
- Verify the deployed app, not just the local one

### The demo path

```text
/s/next-gen-electronics
   → open the RTX 4070
   → add to cart
   → the cart shows an AI cross-sell for a compatible PSU
   → click it; the PSU is added
   → checkout, pay with a Razorpay test card
   → order confirmed
   → merchant dashboard shows AI-attributed revenue
```

Seven steps. If any needs explaining, the UI is doing too little.

## Decisions to make at expansion

1. **Production seed.** Same deterministic seed, or a trimmed demo dataset? The
   seed's `at()` helper anchors to the current day, so timeline-dependent state
   drifts if the production database is seeded once and left.
2. **Demo account reset.** A public demo accumulates junk carts and orders. A
   scheduled re-seed, a reset button, or accept the drift?
3. **Cost control.** The Anthropic key is live on a public URL. Rate-limit
   generation, cache per opportunity, or gate it behind the demo account.
   **Decide before deploying, not after a surprise bill.**

## Out of scope

Custom domain, CI/CD beyond the platform default, monitoring, error tracking,
performance work, load testing.

## Acceptance (sketch)

- The deployed URL serves all four storefronts
- The full demo path completes **on the deployed app**
- Attributed revenue appears on the deployed dashboard
- No secret is present in the repository — verify with a history scan, not just
  a glance at the working tree
- README's first screen shows the demo link and the GIF
- A colleague can follow the walkthrough without help
