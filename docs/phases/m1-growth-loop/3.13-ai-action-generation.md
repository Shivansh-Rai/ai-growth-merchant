# Phase 3.13 — AI Action Generation

**Status:** DRAFT — expand to READY before implementing
**Milestone:** M1 Growth loop
**Requires:** 3.12
**Unlocks:** 3.14

## Goal

An Opportunity plus an application-built candidate set goes to Claude, which
returns a structured decision that the application validates before writing an
`AiAction`.

**The first real model call in the project.**

## Scope

- `lib/growth/actions/build-candidate-set.ts` — store-scoped, purchasable-only
  candidates. This is the guardrail that makes "AI cannot invent products"
  structural rather than a prompt instruction
- `lib/growth/actions/decision-schema.ts` — Zod schema for the model's output
- `lib/growth/actions/generate-action.ts` — call, validate, persist
- Persist: `decision`, `actionType`, `targetProductId`, `rationale`,
  `confidence`, `proposedOffer`, `observedStockQuantity`, `surface` (set by the
  app to `CART`), model metadata, `candidateSetHash`
- Status: `GENERATED`. Guardrails run in 3.14
- `AuditEntry(AI_ACTION_GENERATED)`

### The output contract

```text
{ decision: "ACT" | "NO_ACTION",
  actionType,
  targetProductId,   // MUST be in candidateProductIds
  rationale,         // concise, internal
  confidence,        // informational only, never a business rule
  proposedOffer? }
```

Rejected before any write: `targetProductId` outside the candidate set, an
unknown `actionType`, malformed JSON. `NO_ACTION` is a **valid recorded
decision** (AI-4) and gets a row with `actionType` and `surface` null.

## Decisions to make at expansion

1. **Model choice and cost.** Which Claude model, and what a generation costs.
   Record it — an interviewer will ask.
2. **Retry on invalid output.** One structured retry, or fail to `NO_ACTION`?
   Failing closed is more defensible and simpler.
3. **`proposedOffer` shape.** ADR-2.7-023 fact #1. Fix the JSON shape now so
   3.14 can validate it against `MAX_DISCOUNT`.
4. **Where generation is triggered.** Synchronous after detection blocks the
   add-to-cart response on a model call — probably wrong. Decide, and record.
5. **What goes in the prompt.** Enumerate it explicitly: opportunity evidence,
   candidate products with specs and stock, recent action history. Cost and
   margin may be included for offer reasoning (PRD-6 permits internal use) —
   decide whether they are needed at all, and note that they must never reach
   `rationale`.

## Out of scope

Guardrail evaluation — 3.14. Rendering — 3.15. Streaming, tool use, multi-turn,
agentic loops, fine-tuning, evaluation harnesses.

## Acceptance (sketch)

- A real generation against a seeded opportunity produces a valid `AiAction`
- A stubbed response naming a product **outside** the candidate set is rejected
  and nothing is written
- A stubbed `NO_ACTION` writes a row with null `actionType` and null `surface`
  and violates no CHECK
- `observedStockQuantity` matches the product's stock at generation time
- `rationale` contains no chain-of-thought and no cost or margin figure —
  inspect the stored text
- Model metadata and `candidateSetHash` are populated
- Candidate set contains only purchasable products from the right store
