# Phase 3.6 — Store Context & Storefront Shell

**Status:** READY
**Milestone:** M1 Growth loop
**Requires:** 3.5
**Unlocks:** 3.7, 3.8, 3.9

## Goal

`/s/next-gen-electronics` serves a real, anonymous-browsable storefront reading
live products from the database, with a per-store session cookie established on
first contact.

**This is the first phase where the application actually runs.** Everything
before it was groundwork.

## Contracts

```ts
// lib/store/resolve-store.ts
export type ResolvedStore = {
  id: string;
  name: string;
  slug: string;
  defaultLowStockThreshold: number;
};
/** The ONLY way a storefront request learns its storeId (PLT-3). */
export async function resolveStoreBySlug(slug: string): Promise<ResolvedStore | null>;

// lib/storefront/availability.ts
export type Availability = "IN_STOCK" | "LOW_STOCK" | "OUT_OF_STOCK";
export function availabilityOf(
  stockQuantity: number,
  lowStockThreshold: number | null,
  storeDefaultThreshold: number,
): Availability;
export function isPurchasable(
  lifecycleStatus: ProductLifecycleStatus,
  stockQuantity: number,
): boolean;

// lib/storefront/product-projection.ts
/**
 * Customer-facing shape. The absence of costPricePaise, profit and margin is
 * STRUCTURAL, not a convention — this type is the boundary (PRD-6, F-28).
 * Never widen it to include merchant-only fields.
 */
export type StorefrontProduct = {
  id: string;
  name: string;
  slug: string;
  description: string;
  sku: string;
  mrpPaise: number;
  sellingPricePaise: number;
  discountPaise: number;       // derived
  discountPercent: number;     // derived, rounded for display only
  availability: Availability;
  isPurchasable: boolean;
  specs: Record<string, string | number | boolean> | null;
  primaryImage: { url: string; altText: string } | null;
  brandName: string | null;
  categoryName: string;
};
export function toStorefrontProduct(
  product: Product & { images: ProductImage[]; brand: Brand | null; category: Category },
  storeDefaultThreshold: number,
): StorefrontProduct;

// lib/storefront/session-cookie.ts
/** Cookie name is per-store so no token is shared across merchants (PLT-4). */
export function anonymousCookieName(storeId: string): string;
/** Reads the token, starts a Session if needed, touches it otherwise. */
export async function ensureStorefrontSession(store: ResolvedStore): Promise<Session>;
```

### Listing and detail queries

Both must filter `lifecycleStatus: "ACTIVE"` and `storeId`. `DRAFT` and
`ARCHIVED` products are invisible to customers; an `OUT_OF_STOCK` ACTIVE product
**stays visible** — that is what makes substitution possible later (catalog §6).

Product detail resolves by `(storeId, slug)`, never by id alone.

## Invariants to enforce

| # | Rule | Enforced by |
|---|---|---|
| PLT-3 | `storeId` from the route only — never a body, query param or header | `resolveStoreBySlug` is the single entry point |
| PLT-4 | Anonymous tokens are per-store | Cookie name includes the store |
| PRD-6 | Cost, profit, margin never reach a customer surface | `StorefrontProduct` has no such fields |
| PRD-8 | Availability derived, never stored | `availabilityOf()` |
| catalog §6 | Storefront visibility = ACTIVE | Every query filters it |

## Out of scope

- Cart, add-to-cart buttons, checkout — phases 3.9, 3.10
- Login, register, account pages — phase 3.8
- Event emission — phase 3.7 (this phase renders; it does not track)
- Search and filters — not in M1
- AI suggestion slots — phase 3.15
- Styling beyond "legible and not embarrassing"

## Acceptance

```bash
npx tsc --noEmit
npm run lint
```

Then run the app and verify in the browser preview:

| Check | Expected |
|---|---|
| `/s/next-gen-electronics` | Lists ACTIVE products only |
| `/s/daily-dairy` | Lists **dairy** products — a different catalogue entirely |
| `/s/fresh-harvest` | Shows unbranded produce; no crash on `brandId: null` |
| `/s/no-such-store` | 404, not a crash |
| Product detail for an out-of-stock item | Page renders, marked unavailable |
| A DRAFT product's slug | 404 |
| View source / network payload | **No `costPricePaise`, no margin, no profit anywhere** |
| Reload the page | Same anonymous cookie; a second Session row is not created on every request |
| Visit two stores in one browser | Two different cookies, two different tokens |

The merchant-only leak check is the important one — inspect the actual RSC
payload, not just the rendered HTML.
