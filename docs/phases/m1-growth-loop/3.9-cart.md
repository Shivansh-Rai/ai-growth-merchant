# Phase 3.9 — Cart

**Status:** READY
**Milestone:** M1 Growth loop
**Requires:** 3.7, 3.8
**Unlocks:** 3.10, 3.12

## Goal

An authenticated customer can add, adjust and remove items in exactly one ACTIVE
cart per store, with no inventory reserved and no price stored on the cart.

## Authority

| Rule | Source |
|---|---|
| Cart states, one ACTIVE per `(storeId, customerId)`, one row per `(cartId, productId)`, cart price is not financial truth | [ADR-2.7-015](../../architecture/phase-2.7-decisions.md#adr-27-015--cart-lifecycle--uniqueness) |
| No inventory reservation on add-to-cart | [ADR-2.7-019](../../architecture/phase-2.7-decisions.md#adr-27-019--inventory-concurrency) |
| Server validates ownership, lifecycle, inventory; client prices never trusted | CO-1…CO-6, [activity-tracking §6.4](../../architecture/activity-tracking.md) |
| Commerce requires an authenticated Customer | INV-10, [identity-model §4](../../architecture/identity-model.md) |
| Purchasability | PRD-9 |

## Why CartItem stores no price

`CartItem` deliberately has no price column. The price observed when the item was
added already lives on the `ADD_TO_CART` Event; storing it again would give one
fact two homes, and checkout recalculates from `Product` regardless
(ADR-2.7-015). If the cart UI wants to show a price, it reads `Product` now.

## Contracts

```ts
// lib/cart/get-active-cart.ts
/**
 * Returns the customer's ACTIVE cart, creating one if none exists.
 * Concurrency-safe: the partial unique index is the arbiter, so handle the
 * unique violation by re-reading rather than by checking first (check-then-act
 * races under concurrent requests).
 */
export async function getActiveCart(storeId: string, customerId: string): Promise<Cart>;

// lib/cart/add-item.ts
export type AddItemInput = {
  storeId: string;
  customerId: string;
  productId: string;
  quantity: number; // integer >= 1
};
/**
 * Upserts on (cartId, productId) — a second add INCREMENTS the existing row
 * rather than inserting a duplicate (ADR-2.7-015).
 *
 * Validates: product in this store, ACTIVE, purchasable. Does NOT reserve
 * inventory and does NOT block on insufficient stock — checkout is where
 * inventory becomes binding (ADR-2.7-019).
 */
export async function addItem(input: unknown): Promise<CartItem>;

// lib/cart/update-quantity.ts
/** quantity must be >= 1. Removing is remove-item, not quantity 0. */
export async function updateQuantity(input: unknown): Promise<CartItem>;

// lib/cart/remove-item.ts
export async function removeItem(input: unknown): Promise<void>;

// lib/cart/cart-view.ts
export type CartLineView = {
  productId: string;
  name: string;
  slug: string;
  quantity: number;
  /** Read from Product NOW. Indicative only — checkout recalculates. */
  unitPricePaise: number;
  lineSubtotalPaise: number;
  availability: Availability;
  isPurchasable: boolean;
  primaryImage: { url: string; altText: string } | null;
};
export type CartView = {
  cartId: string;
  lines: CartLineView[];
  /** Sum of line subtotals. NOT an order total — no discounts, no tax. */
  indicativeSubtotalPaise: number;
  itemCount: number;
  /** Lines that can no longer be bought, surfaced rather than silently dropped. */
  hasUnpurchasableLines: boolean;
};
export async function getCartView(storeId: string, customerId: string): Promise<CartView>;
```

Every mutation calls `requireCustomer(storeId)` first and emits the matching
Event via `recordEvent` (`ADD_TO_CART`, `REMOVE_FROM_CART`), and the cart page
emits `CART_VIEW`.

**Unpurchasable lines are shown, not removed.** A product that went out of stock
while sitting in the cart stays visible and flagged — silently deleting a
customer's line is worse than telling them.

## Invariants to enforce

| # | Rule | Enforced by |
|---|---|---|
| CO-1/CO-2 | No anonymous cart | `requireCustomer` at every entry point |
| CO-3 | Product belongs to the same Store | Composite `(storeId, productId)` lookup |
| CO-4 | Product ACTIVE and purchasable to be added | Service check |
| CO-5 | Client prices never trusted | No price accepted in any input |
| ADR-2.7-015 | One ACTIVE cart per `(storeId, customerId)` | Partial unique index; handle the violation, don't pre-check |
| ADR-2.7-015 | One row per `(cartId, productId)` | Unique constraint + upsert |
| ADR-2.7-019 | Add-to-cart reserves nothing | No stock write anywhere in this phase |
| — | `quantity > 0` | Zod + existing CHECK |

## Out of scope

- Checkout, totals, discounts, tax — phase 3.10
- Any inventory mutation — phase 3.11
- Applying an AI offer to a line — phases 3.14, 3.15
- Abandonment / expiry sweep (ACTIVE → ABANDONED after 7 days) — M2
- Saved carts, wishlists, guest carts

## Acceptance

```bash
npx tsc --noEmit
npm run lint
npm run db:verify
```

| Check | Expected |
|---|---|
| Add to cart while logged out | Rejected server-side — test the **API directly**, not just the hidden button |
| Add the same product twice | One `CartItem` row, quantity 2 |
| Add a product from another store's id | Rejected |
| Add a DRAFT or ARCHIVED product | Rejected |
| Add an out-of-stock ACTIVE product | **Allowed** — no reservation (ADR-2.7-019) |
| Cart page after adding | Live prices from `Product`, correct subtotal |
| Change a product's price in the DB, reload cart | New price shown — the cart is not a price snapshot |
| Two concurrent `getActiveCart` calls for one customer | Exactly one ACTIVE cart; no unique-violation crash |

For the concurrency check, fire the two calls with `Promise.all` from a
throwaway script and paste the result.

New `db:verify` assertions: no customer has two ACTIVE carts; no `CartItem`
whose product belongs to a different store.
